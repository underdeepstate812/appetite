# @apetite/mobile

Expo + React Native + TypeScript. Каркас — ШАГ 7, основной сценарий — ШАГ 8,
разрешения и push-уведомления — ШАГ 9. Дизайн-рефреш (RU по умолчанию, новая
палитра, сковорода вместо корзины, реальная карта) — после ШАГ 14, см. ниже.

## Стек

- **Expo SDK 57** (React Native 0.86, React 19) — версии подобраны `expo install`,
  гарантированно совместимы друг с другом.
- **React Navigation v7** — native-stack (Auth-стек, root-стек с OfferDetail/Checkout/
  OrderConfirmation/OrderDetail) + bottom-tabs (Home/Map/Orders/EcoProfile/Profile).
- **Zustand** — стейт-менеджмент (`useAuthStore` — токены, текущий пользователь).
- **react-i18next** — RU/EN. RU — жёсткий дефолт при старте (`DEFAULT_LOCALE`), не
  автоопределение по локали устройства: явный выбор — переключатель в Profile
  (`languageStore.ts`, тот же zustand+persist паттерн, что и у темы).
  `expo-localization` убран из зависимостей — стал не нужен вместе с автоопределением.
- **expo-location** — геопозиция для nearby-поиска, полноценный UX разрешений
  (rationale-баннер, "заблокировано навсегда" → deep link в Settings) — ШАГ 9.
- **expo-notifications** — push-разрешение + регистрация Expo push-токена
  (`POST /notifications/push-token`), тап по уведомлению → навигация — ШАГ 9.
- **react-native-maps** — карта на native; на web у библиотеки нет реализации (её
  `MapView.web.ts` — пустая заглушка `UnimplementedView`), поэтому на web —
  **Leaflet + OpenStreetMap** (`LeafletMapView.tsx`) — настоящая интерактивная
  карта, бесплатно и без API-ключа/аккаунта (в отличие от Yandex Maps JS API,
  который требует завести Yandex-аккаунт — не то, что можно сделать за
  пользователя). Список под картой остался для быстрого сканирования по расстоянию.
- **expo-secure-store** (iOS/Android) / **AsyncStorage** (web) — хранение
  access/refresh токенов, платформенно-специфичный выбор в `store/tokenStorage.ts`.
- Собственная лёгкая тема (`theme/tokens.ts`) — светлая/тёмная, с ручным
  переключателем System/Light/Dark в Profile (`store/themeStore.ts`, zustand +
  persist в AsyncStorage) поверх системной `useColorScheme()`; прокинута и в
  React Navigation (`theme/navigationTheme.ts`), чтобы хедеры/таб-бар тоже
  темизировались, а не только экраны. В палитре — soft-tint варианты акцентных
  цветов (`primarySoft`/`successSoft`/`warningSoft`/`dangerSoft`) для фоновых
  плашек/бейджей, отдельные от насыщенных цветов текста/иконок поверх них.

## Полный сценарий (ШАГ 8) — реально работает, не заглушка

- **Home**: переключатель «Сейчас» (pickupStart уже наступил) / «Вечерние» (начнётся
  позже сегодня), фильтр по категории, реальный гео-поиск (`GET /offers/nearby`) с
  фолбэком на центр Москвы, если геопермишен не выдан/недоступен (типично для web-превью).
- **Карточка оффера**: countdown до `pickupEnd` с цветовой индикацией (<1ч — красный,
  1–2ч — оранжевый, тикает раз в 30 сек через `useNow`), остаток, скидка, дистанция.
- **Checkout → оплата (mock) → подтверждение с QR**: `POST /orders` → `qrCodeDataUrl` +
  `pickupCode` на отдельном экране (`navigation.replace`, чтобы "назад" не возвращал
  на форму оплаты; "Готово" делает `reset()` стека на вкладку Orders).
- **Мои заказы**: список со статусами (`useFocusEffect` — обновляется при каждом
  возврате на экран), деталь заказа — QR повторно + отмена (`PATCH /orders/:id/cancel`).
- **Таймлайн выдачи** (`OrderStatusTimeline`, на экранах подтверждения заказа и деталей
  заказа): 3 стадии — Оплачено → Готовится → Можно забирать, стадия вычисляется на
  клиенте из `pickupStart`/`pickupEnd` (у `Order.status` нет отдельных статусов на эти
  промежуточные состояния). На стадии "можно забирать" — пульсирующая анимация круга
  (`Animated.loop`, только `transform: scale` + `useNativeDriver: true`, без просадки
  кадров ни на native, ни на web) и зелёная soft-tint плашка с временем до конца окна
  самовывоза.
- **Эко-профиль**: реальные баллы/кг/уровень с `GET /eco/me` (новый backend-эндпоинт,
  см. ниже) — прогресс-бар до следующего уровня, из четырёх (Новичок → Спасатель еды →
  Герой планеты → Легенда Apetite).
- **Карта**: на native — `react-native-maps` с маркерами (не проверено вживую — нет
  iOS/Android-симулятора в этом окружении); на web — список по расстоянию с честной
  пометкой, что интерактивная карта доступна в мобильном приложении.

## Разрешения и push-уведомления (ШАГ 9)

- **Гео**: `useLocation` больше не запрашивает пермишен автоматически при монтировании —
  только читает текущий статус (`undetermined`/`denied`/`blocked`/`granted`), чтобы
  системный диалог не выскакивал раньше, чем пользователь увидит объяснение.
  `LocationPermissionBanner` (на Home и Map) показывает rationale и кнопку — цвет
  меняется по серьёзности: `warningSoft`/`warning` пока можно спросить снова
  ("Разрешить"), `dangerSoft`/`danger` когда система заблокировала намертво
  ("Открыть настройки" → `Linking.openSettings()`). При успешном гранте координаты
  синхронизируются в `PATCH /users/me/location` (best-effort, не блокирует UI) — это
  питает гео-дайджест "рядом с тобой N предложений" из ШАГ 6.
- **Push**: `usePushNotifications` запрашивает разрешение после входа, получает
  Expo push-токен и регистрирует его (`POST /notifications/push-token`). Тап по
  уведомлению — навигация на заказ (`data.orderId`) или на Home, если это дайджест
  без конкретного заказа.
- **Экран «Уведомления»**: значок-колокольчик на Home с бейджем количества
  непрочитанных (`useUnreadNotificationsCount`, обновляется по фокусу экрана + раз в
  минуту), фильтр Все/Непрочитанные, тап помечает прочитанным
  (`PATCH /notifications/:id/read`) и переходит по `data.orderId`. Непрочитанные
  строки визуально приподняты (`surfaceElevated` + тонкая `primarySoft`-рамка + точка
  акцентным цветом) — первое реальное применение токена `surfaceElevated`,
  заведённого в палитру ещё в ШАГ 8, но не использованного тогда.

⚠️ Реальный Expo push-токен требует EAS `projectId` (в этой бете не настроен — на
бэкенде тоже `EXPO_PUSH_MODE=mock`) и физическое устройство; на web/без `projectId`
`getExpoPushTokenAsync` ожидаемо падает — тогда просто не регистрируем токен, без
краша (проверено в консоли: `[expo-notifications] Listening to push token changes is
not yet fully supported on web` — предупреждение, не ошибка). Остальной push-флоу
(permission, тап-навигация) от токена не зависит.

## Дизайн-рефреш: язык, цвета, сковорода, карта (после ШАГ 14)

По прямому запросу — четыре независимых изменения, один заход:

- **RU по умолчанию** — см. `react-i18next` в стеке выше. Переключатель языка в
  Profile рядом с темой.
- **Новая палитра акцента**: `primary` `#FF6B4A` (пастельный коралл) →
  `#EA580C` (насыщенный terracotta-orange, Tailwind `orange-600`). Не только
  "посвежее" — у старого цвета hue был всего в ~11° от `danger` (`#D64545`),
  акцент и ошибку было легко перепутать; у нового — ~21°, дальше и чище.
  `primarySoft`/`primarySoftDark` пересчитаны под новый тон.
- **Сковорода вместо корзины** — `FryingPanIcon` (`react-native-svg`, круг +
  ручка, без внешних PNG/эмодзи-зависимостей) заменила эмодзи 🛍️ на стадии
  "можно забирать" в `OrderStatusTimeline`. На экране оформления заказа —
  `CookingLoader`: та же сковорода, кусочек еды подпрыгивает на ней (жарка),
  пар — двумя штрихами со сдвигом по фазе; `submitting` в `CheckoutScreen`
  подменяет форму оплаты этой анимацией на ≥1100мс (`MIN_COOKING_MS`) — mock-оплата
  сама по себе почти мгновенна, без искусственного пола анимация просто
  мигнёт и никто её не увидит. Один и тот же мотив в обоих местах намеренно:
  "готовим" при оформлении → та же сковорода отмечает "готово" в таймлайне.
- **Оплата продумана предметно**: `PaymentMethodSelector` — выбор между
  банковской картой и СБП (система быстрых платежей — стандарт для RU-рынка)
  на экране оформления. Выбор не меняет поведение backend (`PaymentProvider`
  как был mock, так и остался) — это честная, привычная UI-форма выбора,
  а не имитация реальной маршрутизации платежа, которую не имеет смысла
  строить поверх мок-провайдера.
- **Настоящая карта на web** — см. `react-native-maps` в стеке выше.
  Маркеры — свои `L.divIcon` с процентом скидки в цвете темы, не дефолтные
  PNG-иконки Leaflet (у них классическая проблема резолва пути через
  бандлер — на нашем стеке тоже вылезла бы). Тап по маркеру → `OfferDetail`,
  как и по карточке в списке.

⚠️ Нашёл и исправил race condition в `LeafletMapView`: карта создаётся
асинхронно (`import("leaflet")` — динамический, чтобы не тянуть Leaflet в
native-бандл), а эффект, расставляющий маркеры, был завязан только на
`[offers, theme, onSelectOffer]` — при первом рендере он успевал отработать
и выйти (`mapRef.current` ещё `null`) до того, как карта готова, и больше не
перезапускался: маркеры молча не появлялись, хотя сама карта и тайлы рисовались
нормально (заметно только по факту — 0 элементов `.apetite-marker` в DOM).
Добавлен `mapReady`-стейт, выставляется после успешной инициализации карты и
входит в зависимости эффекта с маркерами.

OpenStreetMap-тайлы (`tile.openstreetmap.org`) — бесплатно для dev/демо-объёма
этого масштаба; у прямого использования тайл-сервера есть usage policy для
серьёзного прод-трафика (см. их [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)) —
при реальном пилоте стоит переехать на платный тайл-провайдер или self-host.

## Заставка, приветствие и карта с карточками (октябрь 2026)

- **Заставка с нашим знаком.** Нативная (`expo-splash-screen`, тот же фон `#052e2b` и знак, что в `app.json`) уступает место
  JS-заставке `components/boot/BootSplash`: пин «парит», от острия идёт «пинг». Показывается с первого кадра, держится минимум
  ~0,9 с (без вспышки), уходит, когда готовы шрифты и сессия; при «уменьшить движение» — короткая вспышка. Иконки и сплэш
  (`assets/*.png`) генерируются `assets/source/build-brand-assets.py` из векторного знака — менять знак там, а не в PNG.
- **Страница перед входом** (`screens/auth/WelcomeScreen`) — одна мысль и два действия: арт — карта города
  (`WelcomeCityMap`: Нева с каналами, парки-прямоугольники, кварталы двух сеток, проспекты, подписи, метки предложений на улицах
  и пунктирный маршрут от точки «вы здесь» в центре к скидке; геометрия детерминирована — `utils/cityMap.ts`), пунктирный
  круг из точек по кромке и три наклейки на якорях. Знака-маркера в центре и абстрактных «клякс»-изолиний нет (убраны по просьбе); заголовок с ember-цифрой, «Войти» и «Создать аккаунт»
  в зоне большого пальца. Кнопки пульсируют по очереди (`Button pulse`; ничего не мигает при reduce-motion, disabled и loading).
  Неавторизованного встречает именно она; вход/регистрация открываются с неё и возвращают «Назад».
- **Лента на «Сейчас»**: над картой «проезжает» лента карточек открытых предложений (`components/home/OfferRibbon`,
  `utils/ribbon.ts`, `hooks/useMarquee.ts`): бесшовная петля (набор повторяется, копии скрыты от скринридера и из Tab),
  ≈34 px/с на native driver, края гаснут в фон. Замирает под пальцем, указателем и **клавиатурным** фокусом (фокус от касания
  не держит: он остаётся после тапа), стоит, пока открыта другая вкладка, при reduce-motion или < 3 предложений — обычная
  прокрутка. Ловушки: RN-web у Pressable смотрит на `tabIndex`, а не на `focusable`; Playwright не кликает по уезжающему
  элементу («not stable») — вести указатель на карточку и жать, как человек; карточки ленты — `role=button` с «₽» в подписи,
  поэтому QA-селекторы строк списка исключают `[data-testid=offer-ribbon]`.
- **Экран входа/регистрации**: фон героя — «небо» по времени суток (`DayHeroArt` + `utils/dayPhase.ts`): рассвет → день → золотой
  час → закат → ночь со звёздами; диск — солнце или луна, стоящие там, где они в этот час; цвета плавно перетекают между
  ключевыми часами. Жар показанного предложения красит гало диска и «планету» на орбите. Постер проводит до шести настоящих
  предложений разных заведений быстро (≈3,2 с на карточку, въезд справа / уход влево, полоски «как в историях», пауза пока палец
  держит постер, без автосмены при reduce-motion). Проверка неба в любой час: `shift_clock` в `qa/qa_mobile_auth.py`.
- **Карта**: на весь экран под статус-бар, стеклянная шапка, внизу лента компактных карточек (`components/map/*`,
  логика одна для web и native в `screens/map/MapExperience`). Листаешь ленту — карта летит к предложению; тап по пину —
  лента подъезжает к его карточке; **тап по соседней карточке выбирает, по выбранной — открывает**. Ближайшие первыми
  (с геопозицией), иначе горящие. Web — Leaflet, native — `react-native-maps` (`NativeMapSurface`).
  ⚠️ Native-карта не проверена на устройстве: нет симулятора; покрыта типами, jest и `expo export` (ios/android).
- Ловушки (найдены QA): на web касание фокусирует кнопку ДО клика — «выбор по фокусу» только для клавиатуры (`isKeyboardFocus`),
  иначе тап открывал чужую карточку; RN-web подменяет DOM-`scrollTo` у ScrollView на RN-вариант `{x, y}` — в QA звать
  `Element.prototype.scrollTo`; `accessibilityElementsHidden`/`importantForAccessibility` на web не работают — нужен `aria-hidden`;
  `role=list` без `listitem`-детей ломает axe — у ленты `role="group"`.
- Проверка: `python3 qa/qa_mobile_welcome.py`, `python3 qa/qa_mobile_map.py` (и весь набор `qa/qa_mobile*.py`).

## Завтрак, режим скидки, автовыкладка (октябрь 2026)

- **Вкладка «Завтрак»** на «Сейчас» (`HomeScreen.tsx`, `useBreakfastTime`): видна 00:00–10:00 по Москве,
  в 10:00:00 исчезает сама (точный таймер до границы, не опрос). Если была выбрана — откат на «Сейчас».
  Завтрак — оффер, у которого самовывоз заканчивается сегодня не позже 10:00 и ещё не закрыт.
  Вкладка показывается и пустой (с пояснением); такие офферы остаются и в «Сейчас»/«Вечерних».
  Правила — в `packages/shared/src/schedule.ts` (`isBreakfastTime`, `isBreakfastOffer`, `msUntilBreakfastFlip`).
- **Режим скидки** оффера: `DYNAMIC` (растёт к концу: +10 п.п. за <2 ч, +20 за <1 ч, потолок 70%) или `FIXED`
  (одна на всё время). На экране оффера подпись `DiscountNote` честно говорит, какой режим и когда следующая ступень.
  Логика одна для backend и клиентов: `packages/shared/src/discount.ts`.
- **Автовыкладка** — шаблоны `OfferSchedule` в кабинете бизнеса (дни недели, время, «показывать на витрине за N часов»,
  пропуск дат, пауза). Backend каждые 5 минут создаёт офферы по шаблонам идемпотентно (`scheduleId + occurrenceDate`).
  Для покупателя это обычные офферы; в мобильном приложении ничего отдельно включать не нужно.
- Проверка: `qa/qa_mobile_breakfast.py`, `qa/qa_admin_schedule.py`.

## Быстрый старт

```bash
cp .env.example .env   # EXPO_PUBLIC_API_BASE_URL — на физическом устройстве заменить
                        # localhost на IP компьютера в локальной сети
pnpm dev:mobile         # интерактивный Expo CLI: w — web, i — iOS, a — Android
```

Backend должен быть поднят (`docker compose up -d` или `pnpm dev:backend`) — без него
экраны с данными не смогут ничего загрузить (ошибка сети, не краш приложения).

**Показать по внешней ссылке (туннель).** Адрес API Expo вшивает в бандл при старте, поэтому нужны ДВА туннеля и перезапуск
с переменной: `cloudflared tunnel --url http://localhost:3000` (API) → `EXPO_PUBLIC_API_BASE_URL=<адрес-API>/api/v1 npx expo start --web --port 8082`
→ `cloudflared tunnel --url http://localhost:8082` (приложение). Адреса `trycloudflare.com` меняются при каждом запуске и первые
1–2 минуты могут не открываться; закрыть доступ — остановить `cloudflared`. На чужом адресе тестовые пароли не вводим.

## Известные упрощения

- На web `expo-secure-store` не поддерживается → токены в `AsyncStorage` (по факту
  localStorage), менее безопасно, чем на нативе; ожидаемо для dev/web-предпросмотра.
- Количество в заказе всегда 1 (как "сюрприз-пакет" в TGTG) — без степпера.
- `react-native-web`'s `Alert.alert()` — пустая заглушка (колбэки не срабатывают),
  поэтому подтверждение отмены заказа — через `utils/confirm.ts`
  (`window.confirm` на web, `Alert.alert` на native), а не напрямую `Alert.alert`.
- Карта на native (`MapScreen.native.tsx`) не проверена вживую — нет симулятора в
  этом окружении. Код написан по документированному API `react-native-maps`
  (проверил сигнатуры типов перед использованием), но нуждается в проверке на
  реальном устройстве/симуляторе.
- Браузерный preview-инструмент этого окружения сам блокирует запрос гео-пермишена
  (`navigator.permissions.query({name:'geolocation'})` сразу отдаёт `denied`) —
  живьём проверен только "denied"-баннер и happy-path код чтения статуса; настоящий
  "granted" и различение "denied" vs "заблокировано навсегда" (`canAskAgain`) не
  проверены вживую в этом окружении, только по коду и контракту `expo-location`.
- Push-токен не регистрируется на web/без EAS `projectId` (см. выше) — проверено,
  что это не крашит приложение, но сама доставка push через реальный Expo Push API
  не проверена (соответствует `EXPO_PUSH_MODE=mock` на бэкенде).

## Проверка (сделана вживую, не только тестами)

Прогнано через Expo web в браузере против реального backend, полный путь от входа до
самовывоза: логин → Home с реальными дистанциями/countdown → фильтр по категории →
OfferDetail → Checkout → оплата (mock) → экран с QR и pickup-кодом → "Мои заказы"
(новый заказ CONFIRMED) → деталь заказа (тот же QR/код) → подтверждение выдачи со
стороны заведения через `curl` (mobile не имеет business-роли — это Admin-панель,
ШАГ 10) → возврат в "Мои заказы" (статус обновился на COMPLETED без ручного релоада,
`useFocusEffect`) → Эко-профиль (баллы/кг/прогресс посчитаны верно) → RU-локализация
проверена принудительным переключением языка (браузер в этом окружении отдаёт `en`).

Один пункт не проверен до конца: клик "Да, отменить" в диалоге отмены заказа — сам
built-in browser tool намеренно подавляет нативные `confirm()`/`alert()` диалоги
("native JavaScript dialogs are disabled in this browser") в целях безопасности,
так что через него нельзя докликать до "да". Эндпоинт `PATCH /orders/:id/cancel`
уже проверен `curl`'ом в ШАГ 4/5 smoke-тестах; сама mobile-обёртка — однострочный
вызов, структурно идентичный уже проверенным `create`/`complete`.

### ШАГ 9 — проверено вживую

Location-баннер (rationale, цвет по серьёзности) — на Home и Map, в светлой и тёмной
теме. Колокольчик с бейджем непрочитанных — счёт растёт/падает корректно после
прогона `POST /notifications/run-digest` (admin) и ручных `PATCH .../read`. Экран
«Уведомления»: фильтр Все/Непрочитанные, mark-as-read по тапу, тап по уведомлению с
`data.orderId` → верный `OrderDetail`, тап по `NEARBY_OFFERS` (без orderId) → Home.
Визуальная иерархия непрочитанных/прочитанных строк проверена в обеих темах.

Попутно нашёл и исправил реальный баг: `GET /notifications?unreadOnly=false` (именно
так теперь шлёт вкладка "Все") возвращал пустой список вместо всех уведомлений —
`class-transformer`'s `@Type(() => Boolean)` превращает JS-конструктором ЛЮБУЮ
непустую строку query-параметра в `true`. Исправлено явным `@Transform` в
`apps/backend/src/notifications/dto/list-notifications.query.ts`, закрыто
регрессионной проверкой в `smoke-test.sh` (39/39 проходят).

### Дизайн-рефреш — проверено вживую

RU по умолчанию подтверждено буквально с экрана логина — этот браузер отдаёт
`en` (см. выше по документу), но "Вход"/"Пароль" были на русском без единого
переключения языка вручную. Переключатель RU↔EN в Profile — мгновенный
live-свитч (react-i18next `changeLanguage`), проверен в обе стороны, весь UI
включая таб-бар. Новый цвет акцента — на кнопках/бейджах/скидках в светлой и
тёмной теме. Сковорода в `OrderStatusTimeline` — на стадии "можно забирать",
обеих темах. `CookingLoader` — поймана вживую (временно подняв
`MIN_COOKING_MS` до 6000ms для скриншота, затем вернул обратно к 1100):
сковорода с подпрыгивающим "кусочком еды" рендерится и анимируется корректно.
`PaymentMethodSelector` — переключение карта↔СБП, состояние выбора визуально
корректно. Карта на web — реальные тайлы OpenStreetMap вокруг центра Москвы,
4 маркера со скидкой из сида, тап по маркеру → верный `OfferDetail` (сверено
по проценту скидки на маркере против открывшегося оффера).

Про саму карту: маркеры сначала не появлялись вообще (race condition — карта
инициализируется асинхронно, эффект с маркерами не перезапускался, когда она
наконец становилась готова) — не спрятал баг под "потом проверим", нашёл через
`document.querySelectorAll('.apetite-marker').length === 0` в консоли, поправил
(`mapReady`-стейт), переверифицировал скриншотом с явно видимыми пинами.
