# @apetite/web

React + Vite + TypeScript. Публичный маркетинговый сайт (лендинг + вход/регистрация)
для веб-посетителей — отдельное приложение от `@apetite/admin` (рабочий инструмент
персонала заведений) и `@apetite/mobile` (потребительское приложение). Порт 5174.

## Стек

- **React 19 + Vite 6 + react-router-dom** — та же база, что и в `apps/admin`.
- **Без UI-библиотеки** — собственная CSS-система (`styles/global.css`) с
  design-token палитрой, синхронизированной с рефреш-цветами мобильного приложения
  (`--color-primary: #EA580C`).
- **Leaflet — не используется здесь**: смартфон на лендинге — статичная SVG-иллюстрация
  (`PhoneMockup.tsx`), не встроенная карта — сайт демонстрирует продукт, а не
  дублирует функциональность мобильного приложения.
- **Без i18n** — только RU, как и `apps/admin` (та же логика: единственная аудитория
  пилота — русскоязычные пользователи, ШАГ 0).

## Структура

```
src/
  api/          — client.ts (упрощённый fetch-враппер без auto-refresh — публичный
                  сайт, долгоживущих сессий не хранит), auth.ts (login/register/otp)
  utils/        — validation.ts (email/пароль — зеркалит RegisterDto бэкенда),
                  session.ts (localStorage, только имя — для "Привет, {имя}" на успехе)
  hooks/        — useReveal.ts (IntersectionObserver-скролл-reveal, с фолбэком на
                  prefers-reduced-motion)
  components/   — Header (адаптивный, гамбургер-меню на ≤900px), Footer, PhoneMockup
                  (SVG-макет телефона с картой и пин-маркерами скидок),
                  PasswordStrengthMeter
  pages/        — LandingPage, LoginPage, RegisterPage
  styles/       — global.css (токены + примитивы)
```

## Функциональность

- **Лендинг**: hero с интерактивным SVG-макетом телефона (карта + 4 пин-маркера
  скидок), блок "как это работает", блок для бизнеса, FAQ — все секции появляются
  по скролл-reveal.
- **Регистрация**: имя, email, пароль (мин. 8 символов — как в `RegisterDto`
  бэкенда), повтор пароля со сверкой совпадения, индикатор силы пароля.
  Опциональная верификация телефона по SMS-коду прямо в форме — раскрывающийся
  блок дергает `POST /auth/otp/request` → `POST /auth/otp/verify`, и только после
  успешной верификации `phone` уходит вместе с `POST /auth/register` (бэкенд всё
  равно отклонит непроверенный телефон — см. `apps/backend/src/auth/auth.service.ts`).
- **Вход**: email + пароль, `POST /auth/login`, подсказка демо-доступа.

## Разработка

```bash
pnpm dev:web        # http://localhost:5174, ожидает backend на :3000
```

Требует поднятый `apps/backend` (и Redis — для OTP-флоу) для реальных
регистрации/входа; без бэкенда UI полностью работает, формы валидируются
локально, но сабмит покажет ошибку сети.

## Не входит в этот шаг (см. `docs/BACKLOG.md`)

- Docker/compose-обвязка и smoke-тесты для `apps/web` — сайт целиком статический
  после сборки, задел на верификацию через CI, не критично для текущего UI-фокуса.
- Полноценный чек-лист форм (капча на регистрации, rate-limit UI и т.п.).
